# Performance Issues

## Congestion

- Networks run at a predefined speed (e.g., 1000BASE-T operates at 1 Gbps)
- Congestion occurs when multiple links send more traffic than the destination link can handle
- Example: two 1-Gbps links sending to a single 1-Gbps destination — cannot fit 2 Gbps into 1 Gbps
- Excess packets queue into a buffer, but buffers in switches/routers are relatively small
- Once the buffer fills, packets are discarded
- Resolution: increase the size/speed of the network, or decrease the amount of traffic

## Bottlenecks

- "The network is slow" usually means a bottleneck somewhere is causing a slowdown
- Can be difficult to troubleshoot — problem may involve many different technologies:
  - System bus speed
  - CPU speed in a switch or router
  - Storage drive speed (HDD vs SSD)
  - Network link speeds across different locations
- Must examine all parameters between devices to find the bottleneck
- Sometimes obvious, often requires drilling into system details
- The slowest link between two devices is likely the bottleneck holding up throughput for all other networks

> [!NOTE] Example
> **Bottleneck**
>
> - Web transaction response times around 1,500–1,750 ms (almost 2 seconds of delay)
> - Database was consuming most of the time
> - Configuration changes to the database server eliminated the bottleneck
> - Response times dropped to around 500 ms

## Bandwidth and Throughput

- **Bandwidth percentage** — measure of how much a network is being used over a particular amount of time (presented as a percentage)
- **Throughput** — how much data was moved through the network during a time frame
- Methods to monitor bandwidth: gather directly from a switch, use SNMP, or use NetFlow

## Latency

- The delay between the request and the response
- There will always be some latency — it takes time to move information between devices
- Ideally measure response times at every stop along the path
- Allows breaking down delays into smallest parts per segment
- Requires measuring tools in every network link along the path
- Packet captures provide microsecond granularity — shows exactly how long a packet stayed in a device, traversed a network, and forwarded to the next segment

## Packet Loss

- Ideal: all traffic makes it across the network all of the time
- Packet loss/discard: no errors with the packet, but discarded for other reasons
- Causes:
  - Network outage
  - Contention — not enough bandwidth
  - Bad wireless network
  - Bad cable causing corruption — corrupted data is identified at the other side, discarded, and must be re-sent
- Re-sending takes additional time and resources, causing significant application delays

## Jitter

- VoIP calls and live video streams are very sensitive to delay
- Packets should arrive at regular, predictable intervals
- If a packet is lost during real-time communication, it cannot be retransmitted — must be discarded and continue forward
- Effects: clicking noise on phone calls, stutter on live video streams
- **Jitter** — the variation in time between received frames
- Low jitter: packets received at regular intervals with small, consistent delay between them
- High jitter: bursts of packets followed by long delays (e.g., three packets quickly, long gap, three more packets)
- High jitter causes problems hearing on phone calls and stutter during live video
