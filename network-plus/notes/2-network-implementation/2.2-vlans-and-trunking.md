# VLANs and Trunking

## LANs and Broadcast Domains

- A LAN is a group of devices in the same broadcast domain
- Devices connected to a switch are in the same broadcast domain
- Separate switches = separate broadcast domains (cannot communicate directly)

## VLANs (Virtual Local Area Networks)

- Separate broadcast domains on the same physical switch
- Each switch interface is assigned to a VLAN
- Only devices in the same VLAN can communicate with each other
- Identified by number (VLAN 1, VLAN 2, VLAN 3, etc.)
- Reduces cost, space, power, and management — one switch instead of multiple

## 802.1Q Trunking

Problem: connecting VLANs across multiple switches would require one cable per VLAN.

Solution: a trunk — a single physical connection that carries traffic for all VLANs.

### How Trunking Works

1. Device on VLAN 200 sends a normal ethernet frame to the switch
2. Switch adds a VLAN tag (VLAN 200) to the frame before sending it across the trunk
3. Receiving switch reads the tag, removes it, and delivers the frame to the correct VLAN

### VLAN Tag

Normal ethernet frame:

```
| Preamble | SFD | Destination MAC | Source MAC | Type | Payload | FCS |
```

802.1Q tagged frame (VLAN tag inserted after Source MAC):

```
| Preamble | SFD | Destination MAC | Source MAC | _VLAN_ | Type | Payload | FCS |
```

- 12 bits long
- Normal range: VLAN 1–1005
- Extended range: VLAN 1006–4094
- Reserved: VLAN 0 and 4095
- Total usable: 4,094 VLANs

### ISL (Inter-Switch Link)

- Proprietary (Cisco) trunking protocol, predates 802.1Q
- Relatively outdated — any trunk you encounter will likely be 802.1Q

## Default VLAN

- Every switch has a default VLAN (commonly VLAN 1)
- All interfaces belong to the default VLAN until reconfigured

## Native VLAN

- Traffic on the native VLAN traverses a trunk WITHOUT a VLAN tag
- Used for devices that cannot communicate over 802.1Q
- Used for management traffic and switch notification messages
- Must be identical on both sides of a trunk — mismatches cause error messages in the switch log

## Layer 3 Switches

- Combines layer 2 switching (MAC-based forwarding) and layer 3 routing (IP-based forwarding) in one device
- Layer 2 functionality unchanged; layer 3 functionality unchanged — just combined
- Can route between VLANs within the same switch
- Inter-VLAN routing interfaces called SVIs (Switched Virtual Interfaces)
- May need to enable layer 3 functionality (often requires switch restart)
- Routing functionality tends to be less capable than a standalone router
- Good for smaller/remote sites; larger networks still benefit from dedicated routers

## Voice and Data VLANs

Problem: voice over IP and data share the same ethernet connection but have different needs.

- Data: bursty bandwidth usage
- Voice: requires consistent level of access; affected by congestion

### Solution

- Put voice on one VLAN (e.g., VLAN 200) and data on another (e.g., VLAN 100)
- Single cable from switch → phone → computer
- Switch recognizes both phone and computer, uses trunking on the same cable
- Separates voice and data traffic so neither affects the other
- Requires a switch that supports recognizing both phone and computer on the same port
