# Network Address Translation (NAT)

## The Problem

- IPv4 supports only 4.29 billion addresses — completely exhausted
- Estimated 20–30 billion devices connected to the internet
- NAT extends the functionality of IPv4

## RFC 1918 Private IP Ranges

Not routable on the public internet; used internally in homes and businesses.

| Range                         | Typical Use       |
|-------------------------------|-------------------|
| 10.0.0.0 – 10.255.255.255     | Large enterprises |
| 172.16.0.0 – 172.31.255.255   | Mid-size networks |
| 192.168.0.0 – 192.168.255.255 | Home networks     |

## How NAT Works (Standard)

Translates one IP address to a different IP address (private → public).

1. Internal device sends packet with private source IP
2. NAT router receives packet, recognizes private source IP
3. Router translates source IP to an available public IP from its pool
4. Packet goes to destination with public source IP
5. Return traffic comes back to the public IP
6. NAT router translates destination IP back to the original private IP
7. Internal device receives the response

Each internal device using standard NAT requires its own public IP address.

## NAT Overload / PAT (Port Address Translation)

Translates both the IP address AND the port number — allows many devices to share one public IP.

### How It Works

1. Internal device sends packet with private IP + source port (e.g., 10.10.20.50:3233)
2. NAT router translates to public IP + different port (e.g., 94.1.1.1:1055)
3. Router stores mapping in NAT table (private IP:port ↔ public IP:port)
4. Another device (e.g., 10.10.20.70:5782) gets the same public IP but a different port (94.1.1.1:1056)
5. Many internal devices share one public IP — differentiated by port number

> [!NOTE] Example
> **NAT Table**
>
> | Private Address  | Public Address |
> |------------------|----------------|
> | 10.10.20.50:3233 | 94.1.1.1:1055  |
> | 10.10.20.70:5782 | 94.1.1.1:1056  |
>
> Port numbers increment for each new session — same public IP, different port.
