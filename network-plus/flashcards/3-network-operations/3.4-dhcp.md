# DHCP Flashcards

**Q:** What did network administrators have to do before BOOTP/DHCP existed?
**A:** Manually configure all IPv4 settings (IP address, subnet mask, DNS, etc.) on every device
**Difficulty:** Easy
**Tags:** dhcp, background, domain-3, prof-messer

---

**Q:** What is BOOTP?
**A:** Bootstrap Protocol — an early protocol created to automate IP address configuration, predecessor to DHCP
**Difficulty:** Easy
**Tags:** bootp, background, domain-3, prof-messer

---

**Q:** What were BOOTP's two limitations?
**A:** Didn't configure everything automatically, and could not recognize when an IP address became available after a device left the network
**Difficulty:** Medium
**Tags:** bootp, background, domain-3, prof-messer

---

**Q:** What is DHCP?
**A:** Dynamic Host Configuration Protocol — replaced BOOTP to provide full automatic address configuration for all devices on a network
**Difficulty:** Easy
**Tags:** dhcp, domain-3, prof-messer

---

**Q:** What does DORA stand for in DHCP?
**A:** Discover, Offer, Request, Acknowledge — the four steps to obtain an IP address automatically
**Difficulty:** Easy
**Tags:** dora, dhcp, domain-3, prof-messer

---

**Q:** In the DHCP Discover step, what source IP does the client use and why?
**A:** 0.0.0.0 — because the client does not have an IP address yet
**Difficulty:** Medium
**Tags:** dora, discover, dhcp, domain-3, prof-messer

---

**Q:** In the DHCP Discover step, what is the destination IP and why?
**A:** 255.255.255.255 (broadcast) — so all devices on the subnet see it and any DHCP servers can respond
**Difficulty:** Medium
**Tags:** dora, discover, dhcp, domain-3, prof-messer

---

**Q:** What UDP port does the DHCP client use as its source port?
**A:** UDP 68
**Difficulty:** Medium
**Tags:** dora, ports, dhcp, domain-3, prof-messer

---

**Q:** What UDP port does the DHCP server use as its source port?
**A:** UDP 67
**Difficulty:** Medium
**Tags:** dora, ports, dhcp, domain-3, prof-messer

---

**Q:** Why is the DHCP Offer sent as a broadcast?
**A:** Because the client does not yet have an IP address — the only way the client can see the packet is if it's sent to all devices on the subnet
**Difficulty:** Medium
**Tags:** dora, offer, dhcp, domain-3, prof-messer

---

**Q:** What happens if multiple DHCP servers exist on the network during the Offer phase?
**A:** The client may receive multiple offers from different DHCP servers
**Difficulty:** Medium
**Tags:** dora, offer, dhcp, domain-3, prof-messer

---

**Q:** In the DHCP Request step, what does the client do?
**A:** Chooses one of the offers and sends a DHCP Request to that DHCP server
**Difficulty:** Easy
**Tags:** dora, request, dhcp, domain-3, prof-messer

---

**Q:** Does the client have an IP address during the Request step?
**A:** No — source IP is still 0.0.0.0 and the request is sent as a broadcast
**Difficulty:** Medium
**Tags:** dora, request, dhcp, domain-3, prof-messer

---

**Q:** What happens after the client receives the DHCP Acknowledgment?
**A:** The client can now configure all IP settings automatically
**Difficulty:** Easy
**Tags:** dora, acknowledge, dhcp, domain-3, prof-messer

---

**Q:** Are all four DORA messages sent as broadcasts or unicasts?
**A:** All four are sent as broadcasts (255.255.255.255)
**Difficulty:** Medium
**Tags:** dora, dhcp, domain-3, prof-messer

---

**Q:** What is the fundamental limitation of DHCP related to broadcasts?
**A:** Broadcasts only reach the local subnet — they do not traverse routers — so a DHCP server on a different subnet cannot be reached directly
**Difficulty:** Medium
**Tags:** dhcp, limitations, domain-3, prof-messer

---

**Q:** Why is the broadcast limitation a problem for enterprise networks?
**A:** Enterprise networks want redundant or centralized DHCP servers, but broadcasts don't cross routers to reach them
**Difficulty:** Medium
**Tags:** dhcp, limitations, domain-3, prof-messer

---

**Q:** What is DHCP Relay (DHCP Helper)?
**A:** A router feature that forwards DHCP broadcast traffic to a DHCP server on a different subnet
**Difficulty:** Easy
**Tags:** dhcp-relay, dhcp, domain-3, prof-messer

---

**Q:** What must be configured on the router to enable DHCP Relay?
**A:** The IP address of the DHCP server
**Difficulty:** Easy
**Tags:** dhcp-relay, dhcp, domain-3, prof-messer

---

**Q:** How does the router with DHCP Relay convert the client's broadcast into something routable?
**A:** It changes the source IP to its own interface IP and the destination to the DHCP server's IP — converting broadcast to unicast
**Difficulty:** Hard
**Tags:** dhcp-relay, dhcp, domain-3, prof-messer

---

**Q:** How does the DHCP server's response get back to the client through DHCP Relay?
**A:** The server responds with unicast to the router, then the router converts it back to a broadcast on the client's local subnet
**Difficulty:** Hard
**Tags:** dhcp-relay, dhcp, domain-3, prof-messer

---

**Q:** Does DHCP Relay apply to just the Discover step or all four DORA phases?
**A:** All four DORA phases — the relay process repeats for each step
**Difficulty:** Medium
**Tags:** dhcp-relay, dora, dhcp, domain-3, prof-messer

---

**Q:** What does DHCP Relay allow in terms of network design?
**A:** Clients can receive IP addresses from a DHCP server on a completely different subnet
**Difficulty:** Easy
**Tags:** dhcp-relay, dhcp, domain-3, prof-messer

---

**Q:** In DORA, which steps are sent by the client and which by the server?
**A:** Client sends: Discover and Request. Server sends: Offer and Acknowledge.
**Difficulty:** Medium
**Tags:** dora, dhcp, domain-3, prof-messer
