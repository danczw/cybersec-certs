# Introduction to IP Flashcards

**Q:** What is data encapsulation?
**A:** The process of wrapping data within protocols, which are then wrapped within larger protocols — each layer adds its own header (and sometimes trailer)
**Difficulty:** Easy
**Tags:** encapsulation, ip, domain-1, prof-messer

---

**Q:** What is the structure of an Ethernet frame from outer to inner?
**A:** Ethernet Header → IP Header → TCP/UDP Header → Application Data → Ethernet Trailer
**Difficulty:** Medium
**Tags:** encapsulation, ethernet, ip, domain-1, prof-messer

---

**Q:** In the moving truck analogy, what does the road represent?
**A:** The network (wired Ethernet, wireless, WAN, etc.)
**Difficulty:** Easy
**Tags:** encapsulation, ip, domain-1, prof-messer

---

**Q:** In the moving truck analogy, what does the truck represent?
**A:** Internet Protocol (IP) — does the heavy lifting of moving data across the network
**Difficulty:** Easy
**Tags:** encapsulation, ip, domain-1, prof-messer

---

**Q:** In the moving truck analogy, what do the boxes represent?
**A:** TCP or UDP — they package the application data for transport
**Difficulty:** Easy
**Tags:** encapsulation, tcp, udp, domain-1, prof-messer

---

**Q:** What does TCP stand for?
**A:** Transmission Control Protocol
**Difficulty:** Easy
**Tags:** tcp, domain-1, prof-messer

---

**Q:** What does UDP stand for?
**A:** User Datagram Protocol
**Difficulty:** Easy
**Tags:** udp, domain-1, prof-messer

---

**Q:** At which OSI layer do TCP and UDP operate?
**A:** Layer 4 — the Transport layer
**Difficulty:** Easy
**Tags:** tcp, udp, osi, domain-1, prof-messer

---

**Q:** What does "connection-oriented" mean in the context of TCP?
**A:** There is a formal process to set up a connection before data transfer and a formal process to tear it down when done
**Difficulty:** Medium
**Tags:** tcp, connection-oriented, domain-1, prof-messer

---

**Q:** What does "reliable delivery" mean in TCP?
**A:** The receiving device acknowledges receipt of data — the sender always knows if information was properly delivered
**Difficulty:** Medium
**Tags:** tcp, reliable, domain-1, prof-messer

---

**Q:** How does TCP handle lost packets?
**A:** Packets are numbered, so the receiver can request specific missing packets without requiring full retransmission of all data
**Difficulty:** Medium
**Tags:** tcp, error-recovery, domain-1, prof-messer

---

**Q:** What is flow control in TCP?
**A:** The receiving station tells the sender to speed up or slow down transmission based on how well traffic is being received
**Difficulty:** Medium
**Tags:** tcp, flow-control, domain-1, prof-messer

---

**Q:** What happens when a TCP sender doesn't receive an acknowledgment?
**A:** It assumes the data was not received and resends the information
**Difficulty:** Medium
**Tags:** tcp, error-recovery, domain-1, prof-messer

---

**Q:** What does "connectionless" mean in the context of UDP?
**A:** No formal process to set up or tear down a session — data is sent without warning or prior arrangement
**Difficulty:** Medium
**Tags:** udp, connectionless, domain-1, prof-messer

---

**Q:** Why is UDP called "unreliable"?
**A:** Not because it's more likely to fail — it has the same delivery probability as TCP — but because no acknowledgments are sent, so delivery can't be confirmed
**Difficulty:** Hard
**Tags:** udp, unreliable, domain-1, prof-messer

---

**Q:** Can UDP perform error recovery?
**A:** No — since there are no acknowledgments, there's no way to know what was lost or retransmit it
**Difficulty:** Easy
**Tags:** udp, error-recovery, domain-1, prof-messer

---

**Q:** Can UDP perform flow control?
**A:** No — the receiver never sends anything back to the sender, so it can't signal to speed up or slow down
**Difficulty:** Easy
**Tags:** udp, flow-control, domain-1, prof-messer

---

**Q:** Does UDP have a higher chance of packet loss than TCP?
**A:** No — both protocols use the same network with the same probability of successful delivery; the difference is only in feedback mechanisms
**Difficulty:** Medium
**Tags:** udp, tcp, domain-1, prof-messer

---

**Q:** What is multiplexing in the context of networking?
**A:** Sending multiple different applications simultaneously between the same devices using different port numbers at OSI Layer 4
**Difficulty:** Medium
**Tags:** multiplexing, ports, domain-1, prof-messer

---

**Q:** What is a socket?
**A:** A combination of IP address + protocol (TCP/UDP) + port number that identifies one endpoint of a network connection
**Difficulty:** Medium
**Tags:** socket, ip, ports, domain-1, prof-messer

---

**Q:** What is the destination IP address analogous to in the moving truck analogy?
**A:** The house address — which device to deliver to
**Difficulty:** Easy
**Tags:** ip, addressing, domain-1, prof-messer

---

**Q:** What is a TCP/UDP port number analogous to in the moving truck analogy?
**A:** The room within the house — which application on the device should receive the data
**Difficulty:** Easy
**Tags:** ports, domain-1, prof-messer

---

**Q:** What are non-ephemeral ports?
**A:** Permanent, well-known port numbers in the range 0–1,023, typically used by servers (e.g., 80, 443)
**Difficulty:** Medium
**Tags:** ports, non-ephemeral, domain-1, prof-messer

---

**Q:** What are ephemeral ports?
**A:** Temporary port numbers in the range 1,024–65,535, randomly assigned by the OS for client-side connections
**Difficulty:** Medium
**Tags:** ports, ephemeral, domain-1, prof-messer

---

**Q:** What is the full range of TCP/UDP port numbers?
**A:** 0–65,535
**Difficulty:** Easy
**Tags:** ports, domain-1, prof-messer

---

**Q:** Why is the maximum port number 65,535?
**A:** The port field in TCP/UDP headers is 16 bits — 2^16 = 65,536 values, starting at 0
**Difficulty:** Medium
**Tags:** ports, domain-1, prof-messer

---

**Q:** Are TCP port 80 and UDP port 80 the same port?
**A:** No — TCP and UDP port numbers are independent; they could run different applications simultaneously
**Difficulty:** Hard
**Tags:** ports, tcp, udp, domain-1, prof-messer

---

**Q:** Is changing a port number a security mechanism?
**A:** No — you still need a firewall to allow/disallow traffic; changing ports just affects communication, not security
**Difficulty:** Medium
**Tags:** ports, security, domain-1, prof-messer

---

**Q:** What happens if you change a web server's port from 443 to something else?
**A:** Clients can no longer connect by default — browsers expect port 443 for HTTPS; all clients must be reconfigured with the new port
**Difficulty:** Medium
**Tags:** ports, domain-1, prof-messer

---

**Q:** Can a server use ephemeral-range port numbers?
**A:** Yes — non-ephemeral for servers and ephemeral for clients is a convention, not a hard rule
**Difficulty:** Medium
**Tags:** ports, ephemeral, domain-1, prof-messer

---

**Q:** In a practical example, a server runs web (TCP 80), VoIP (UDP 5004), and email (TCP 143). How can a client use all three simultaneously?
**A:** Each application uses a different port number, so the client opens three connections with different ephemeral source ports to different destination ports — multiplexing
**Difficulty:** Medium
**Tags:** multiplexing, ports, domain-1, prof-messer

---

**Q:** When a server responds to a client, how does it know where to send the reply?
**A:** It reverses the source/destination IP addresses and source/destination port numbers from the original request
**Difficulty:** Medium
**Tags:** socket, ports, domain-1, prof-messer

---

**Q:** What is a 5-tuple in networking?
**A:** Source IP + source port + destination IP + destination port + protocol — uniquely identifies a connection
**Difficulty:** Hard
**Tags:** socket, 5-tuple, domain-1, prof-messer

---

**Q:** How can a server handle thousands of connections on the same port (e.g., TCP 443)?
**A:** Each connection has a unique 5-tuple — same server IP/port but different client IP and/or ephemeral port makes each socket distinct
**Difficulty:** Hard
**Tags:** socket, multiplexing, 5-tuple, domain-1, prof-messer

---

**Q:** Who assigns the client's ephemeral port number?
**A:** The OS — it automatically picks a random available port from the ephemeral range when an application initiates an outbound connection
**Difficulty:** Medium
**Tags:** ports, ephemeral, domain-1, prof-messer

---

**Q:** What is a listening socket?
**A:** A socket on a server that waits for incoming connections on a well-known port; when a client connects, the server spawns a new socket for that specific conversation
**Difficulty:** Hard
**Tags:** socket, ports, domain-1, prof-messer

---

**Q:** Name the four features TCP has that UDP lacks.
**A:** Connection setup/teardown, acknowledgments, error recovery, flow control
**Difficulty:** Hard
**Tags:** tcp, udp, domain-1, prof-messer

---

**Q:** Why do servers use well-known (non-ephemeral) port numbers?
**A:** So clients know where to send initial requests — without a predictable port, clients wouldn't know where to connect
**Difficulty:** Medium
**Tags:** ports, non-ephemeral, domain-1, prof-messer
