ARP and DNS Poisoning

4.0 Network Security OBJ 4.2 CompTIA Network+ N10-009

Spoofing

  • Pretending to be another person or device
  • Examples: fake web server, fake DNS server, email address spoofing, caller ID spoofing
  • Commonly used for on-path attacks — sitting in the middle of a conversation to monitor or change its contents
Supplementary

ARP = Address Resolution Protocol — resolves IP addresses to MAC addresses on a local network.

ARP Poisoning (IP Spoofing)

  • Attacker pretends to be an IP address they are not
  • Also called IP spoofing

How ARP Works

  1. Device needs the MAC address of another device it wants to communicate with (only has the IP)
  2. ARP sends a broadcast: "Who has [IP address]? I need that MAC address."
  3. Device with that IP responds with its MAC address
  4. Requester caches the response in a local ARP cache

The Vulnerability

  • No authentication or security in the ARP process
  • ARP accepts any response, even unsolicited ones

ARP Poisoning Attack

  1. Attacker sends an ARP response to the victim — even without a request
  2. Response spoofs the router's IP but contains the attacker's MAC address
  3. Victim's ARP cache is updated with the attacker's MAC for the router's IP
  4. All traffic from victim to router is now sent to the attacker first
  5. Attacker forwards traffic to the legitimate router — neither victim nor router knows

Result

  • On-path attack: attacker intercepts and forwards all traffic between victim and router
  • Neither side realizes there's an attacker in the middle

DNS Poisoning (DNS Spoofing)

  • Modifying information on the DNS server itself, or modifying DNS responses in transit
  • Also called DNS spoofing

Methods

  • Modify the host file on the client — host file has higher priority than DNS responses; entries always take precedence over DNS
  • Send fake responses to legitimate DNS requests — requires changing information on the fly (on-path attack)
  • Hack into the DNS server — change the DNS configuration directly

DNS Poisoning Attack Flow

  1. DNS server contains the legitimate IP for a domain
  2. Attacker either performs ARP poisoning to intercept DNS traffic, or hacks the DNS server directly
  3. Attacker changes the stored IP to the attacker's IP
  4. Subsequent DNS queries return the poisoned address
  5. Victim's cache stores the spoofed IP
  6. Victim communicates with the attacker's server instead of the legitimate one
