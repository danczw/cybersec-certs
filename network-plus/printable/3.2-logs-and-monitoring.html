Logs and Monitoring

3.0 Network Operations OBJ 3.2 CompTIA Network+ N10-009

NetFlow

  • Summary of statistics based on traffic flows traversing the network
  • Standard collection method; many products from many manufacturers
  • Components:
    • Probe: sits on the network via physical tap or SPAN port to capture raw packets and compile statistics
    • Collector: central destination that receives summaries from all probes; stores data over time
    • Report generator: often built into the collector; provides real-time views and long-term scheduled reports
  • Data includes: top conversations (ingress/egress), top endpoints, traffic by port/application, events

Protocol Analyzer

  • Captures and displays raw packets (exact bits and bytes) sent across the network
  • Works on wired and wireless networks
  • Presents data in human-readable summary with drill-down into packet details
  • Use cases: finding unknown traffic, troubleshooting slow applications
  • Some organizations store all captured packets long-term on large storage arrays for later analysis

Network Performance Baseline

  • Picture of what a normal day on the network looks like, built from collected data
  • Useful for troubleshooting — compare current values to what's normal
  • Can drill down to individual device performance
  • Management console or SIEM can identify anomalies by comparing against the baseline

Syslog

  • Standard protocol for transferring log files from network devices to a central location
  • Devices (switches, routers, firewalls, servers) each configured with syslog destination
  • Commonly sent to a SIEM
  • Log entries include:
    • Device identifier (which device sent it)
    • Facility code: the program that created the log entry
    • Severity level: importance of that log entry
  • Sensitivity settings can be adjusted to only capture warning/urgent info and exclude informational details

SIEM (Security Information and Event Manager)

  • Central system collecting log files from many devices
  • Stores data on large drive arrays
  • Capabilities:
    • Real-time dashboard with alerts and alarms (e.g., failed authentications, devices going offline)
    • Advanced reporting — compare and contrast statistics across multiple devices over time
    • Ad hoc queries (e.g., search for "fail*" AND "password" to find authentication failures)
    • Forensics — go back in time to track authentication events and service usage
  • Can track traffic flow across the entire path: server → switch → firewall → internet

API Integration

  • Central management station communicates to devices via Application Programming Interface
  • Eliminates need to SSH into each device individually
  • Enables scripts and programs to send commands, make configuration changes, or query information
  • Essential for large environments (hundreds or thousands of devices)
  • Changes can be applied to many devices automatically with one action

Port Mirroring / SPAN

  • Redirects a copy of traffic from one switch port to another port connected to a monitoring device
  • Also called Switched Port Analyzer (SPAN)
  • Use cases: IDS/IPS, performance monitoring, NetFlow collection
  • Some switches support mirroring traffic from one switch to another (remote SPAN)
  • Can mirror single interfaces, multiple interfaces, or entire VLANs
  • Original traffic is unaffected — only a copy is sent to the monitoring device

Network Tap

  • Physical device connected between two devices to capture traffic
  • Alternative to port mirroring for gathering raw packets
