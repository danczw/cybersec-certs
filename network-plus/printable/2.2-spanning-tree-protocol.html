The Loop Problem

  • Two cables between two switches = loop
  • No mechanism at MAC address level to count how many times a frame has been seen
  • Frames loop endlessly, adding more traffic until switches are overwhelmed
  • Can bring down network in seconds
  • Fix: disconnect the cable creating the loop

STP (IEEE 802.1D)

Automated standard that recognizes and prevents loops on a network.

Port States

  • Blocking — not forwarding any traffic; used to prevent loops
  • Listening — clears existing tables, restarts the process
  • Learning — listens to understand switch topology and detect existing loops
  • Forwarding — traffic can be transmitted through this interface
  • Disabled — administratively disabled; does not participate in STP

Port Roles

  • Root port (RP) — interface on a switch connected ultimately to the root bridge
  • Designated port — any other port that can forward traffic but is not the root port
  • Blocked port — port disabled by STP to prevent a loop

Root Bridge

  • Single switch elected as the reference point for the entire STP topology
  • All other switches determine their root ports based on shortest path to the root bridge

STP Recovery (Topology Change)

  1. Link failure detected (e.g., connection between switches lost)
  2. STP clears existing configuration and relearns the network topology
  3. Blocked ports may become forwarding; root ports may shift
  4. Network recovers without creating a loop

Rapid Spanning Tree Protocol (RSTP / IEEE 802.1W)

  • Original STP convergence: 30–50 seconds
  • RSTP convergence: ~6 seconds
  • Backwards compatible with original STP
  • Works very similarly to STP — just operates much faster
  • Can run alongside original STP on mixed-device networks
