IPv4 Address Families

Everything needed to name an address on sight. Built for printing.

The procedure

Read the first octet. It resolves almost every address by itself. Only two values — 172 and 192 — need a second look, and those two are where exam questions live.

First octetThenVerdict
10nothingPrivate. The whole /8.
127nothingLoopback. Never leaves the host.
169second octet 254?Yes → link-local (APIPA). No → public.
172second octet 16–31?Yes → private. No → public.
192second octet 168?Yes → private. No → public.
224–239nothingMulticast (Class D).
240–255nothingReserved (Class E). Never assigned.
anything elsenothingPublic.

The two traps. 172.32.0.1 is public — the private block stops at 172.31. 192.167.1.1 is public — only 192.168 is private. Both look private at a glance, and that glance is what the exam is testing.

Private ranges (RFC 1918)

CIDRRangeMaskHost bitsTypical use
10.0.0.0/8 10.0.0.0 – 10.255.255.255 255.0.0.0 24 (16M+) Large enterprise
172.16.0.0/12 172.16.0.0 – 172.31.255.255 255.240.0.0 20 (1M+) Mid-size network
192.168.0.0/16 192.168.0.0 – 192.168.255.255 255.255.0.0 16 (65K+) Home network

None of these route on the public internet; they need NAT to translate to a public address first. The /12 is the one worth memorising as a fact rather than deriving: 16 through 31, sixteen /16 networks.

Special-purpose addresses

NameRangeMeans
Loopback 127.0.0.1 – 127.255.255.254 The local device itself. A successful ping proves the local IP stack works and nothing else — not the cable, not the switch, not the gateway.
Link-local (APIPA) 169.254.0.1 – 169.254.255.254
assigned: 169.254.1.0 – 169.254.254.255		 No DHCP server answered. The host self-assigned, using ARP to check nothing else holds the address. Local subnet only — cannot route anywhere.
Reserved (Class E) 240.0.0.1 – 254.255.255.254 Set aside for future use and testing. Never assigned to a device.
Virtual IP (VIP) any Not tied to a physical adapter — assigned to device internals such as VMs and router interfaces.

Address classes

Classful addressing stopped being used for subnet masking in 1993. It is still examinable, and still the starting point for every subnetting calculation.

ClassFirst octetLeading bitsDefault maskNetwork / host bits
A0–1270255.0.0.08 / 24
B128–19110255.255.0.016 / 16
C192–223110255.255.255.024 / 8
D224–2391110— (multicast)—
E240–2551111— (reserved)—

The class boundaries are not arbitrary: each one is where the next leading bit flips on. 128 is 10000000, 192 is 11000000, 224 is 11100000, 240 is 11110000. Recognising those four binary values is the same skill as reading a subnet mask.

What a host needs

Three values to communicate beyond its own subnet: an IP address, a subnet mask, and a default gateway. The gateway must itself be an address on the local subnet. The mask is never transmitted — it is used locally to decide what is on-subnet versus off-subnet, which is the decision that determines whether traffic goes to the gateway at all.
