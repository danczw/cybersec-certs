# Routing Practice Scenarios

## Scenario 1: Small Branch Office Connectivity

**Scenario:** A company opens a new remote office with 15 employees. The office has a single internet connection to headquarters. The network administrator needs to configure routing between the branch and HQ.

**Question:** What type of routing should the administrator use, and why?

**Answer:** Static routing.

**Explanation:** The branch office is a stub network — a remote site with a single connection. Static routing is ideal here because it's quick to configure on small networks, has no overhead from dynamic routing protocols (no CPU cycles, no memory usage), and is relatively secure since there are no dynamic routing updates that could be manipulated. Since there's only one path, automatic rerouting isn't needed.

## Scenario 2: Administrative Distance Tie-Breaking

**Scenario:** A router has learned a route to 10.10.30.0/24 from three different sources: a static route configured by the admin, an OSPF update from a neighboring router, and an EIGRP update from another neighbor. All three routes point to different next hops.

**Question:** Which route will the router prefer? Choose from:

A) The OSPF route (AD 110)
B) The static route (AD 1)
C) The EIGRP route (AD 90)
D) The router will load balance across all three

**Answer:** B) The static route (AD 1)

**Explanation:** When identical routes come from different sources, administrative distance breaks the tie. Lower AD = better. Static routes have AD 1, EIGRP has AD 90, and OSPF has AD 110. The static route wins because it has the lowest administrative distance.

## Scenario 3: Routing Table Interpretation

**Scenario:** A network engineer examines a routing table entry:

```
R      10.10.30.0/24      [120/1]       via 10.10.50.2,  00:00:14,  Serial0/3/1
```

**Question:** Identify the following from this entry: (1) How was this route learned? (2) What is the administrative distance? (3) What is the metric? (4) Where will traffic be forwarded?

**Answer:**
1. The route was learned via RIP (route code "R")
2. Administrative distance is 120
3. Metric is 1 (hop count, since RIP uses hop count as its metric)
4. Traffic will be forwarded to next hop 10.10.50.2 via the Serial0/3/1 interface

**Explanation:** The route code "R" indicates RIP. The bracketed values [120/1] show administrative distance (120) and metric (1) respectively. The "via" address is the next hop, and the final field is the outgoing interface.

## Scenario 4: FHRP Failover

**Scenario:** A company has two routers (Router A and Router B) on the same subnet providing default gateway services via FHRP. Router A is the active router holding the virtual IP address 192.168.1.1. All 200 workstations use 192.168.1.1 as their default gateway. Router A suddenly loses power.

**Question:** What happens to network connectivity for the 200 workstations?

**Answer:** Router B detects the failure of Router A and becomes the active router, taking over the virtual IP address 192.168.1.1. The workstations continue using the same default gateway seamlessly with no reconfiguration needed.

**Explanation:** FHRP creates a virtual IP address shared between routers. The standby router is always communicating with the active router. When the standby detects active router failure, it becomes active and takes over the VIP. End users continue using the same default gateway — failover is seamless. Devices can only configure one default gateway IP, so FHRP solves the redundancy problem without requiring changes on endpoints.

## Scenario 5: NAT Overload / PAT

**Scenario:** A small office has 50 workstations all using private IP addresses in the 10.10.20.0/24 range. The company has only one public IP address: 94.1.1.1. Two employees send web requests simultaneously — one from 10.10.20.50 using source port 3233, and another from 10.10.20.70 using source port 5782.

**Question:** How does the NAT router allow both devices to communicate on the internet using the same public IP? What will the NAT table look like?

**Answer:** The router uses NAT overload (PAT), translating both the IP address and port number. The NAT table maps:
- 10.10.20.50:3233 → 94.1.1.1:1055
- 10.10.20.70:5782 → 94.1.1.1:1056

Both devices share the same public IP but are differentiated by port number.

**Explanation:** PAT (Port Address Translation) translates both the IP address AND the port number, allowing many devices to share one public IP. The router stores each mapping in the NAT table (private IP:port to public IP:port). Port numbers increment for each new session. Return traffic is matched back to the correct internal device using the port mapping.

## Scenario 6: Static vs Dynamic Routing Decision

**Scenario:** A growing enterprise now has 200 routers across 15 sites. The network team spends hours each week updating routes when links are added or removed. Recently, a misconfigured static route caused a routing loop that took down connectivity for an entire building.

**Question:** What routing approach should the enterprise migrate to, and which protocol would you recommend given they use equipment from multiple vendors?

**Answer:** Migrate to dynamic routing using OSPF.

**Explanation:** Static routing is challenging on larger networks with hundreds of routers. It relies on administrators adding correct routes (misconfiguration can create routing loops), and routes don't change automatically — network changes require manual updates to every affected router. Dynamic routing solves these problems: routers automatically discover routes and update each other, and if links are added or removed, routers inform all others. OSPF is recommended because it's an open standard available on many different manufacturers' devices, unlike EIGRP which is Cisco-centric.

## Scenario 7: Most Specific Route Selection

**Scenario:** A router has the following three routes in its routing table:

1. 192.168.0.0/16 via 10.1.1.1
2. 192.168.1.0/24 via 10.2.2.2
3. 192.168.1.6/32 via 10.3.3.3

A packet arrives destined for 192.168.1.6.

**Question:** Which next hop will the router forward the packet to?

A) 10.1.1.1
B) 10.2.2.2
C) 10.3.3.3
D) The router will load balance across all three

**Answer:** C) 10.3.3.3

**Explanation:** When multiple routes match a destination, the most specific prefix wins. A /32 is the most specific possible route (single host), /24 is more specific than /16. The longer the prefix, the more specific the route, and it is always preferred. So 192.168.1.6/32 via 10.3.3.3 is chosen first.

## Scenario 8: Next Hop Determination with Static Routes

**Scenario:** A network has three routers. Router 1 is directly connected to subnets 10.10.10.0/24, 10.10.40.0/24, and 10.10.50.0/24. Router 2 is connected to Router 1 via the 10.10.40.0/24 link (Router 2's interface is 10.10.40.2) and has local subnet 10.10.20.0/24. Router 3 is connected to Router 1 via the 10.10.50.0/24 link (Router 3's interface is 10.10.50.2) and has local subnet 10.10.30.0/24.

A host on 10.10.10.0/24 needs to reach a device at 10.10.20.5.

**Question:** What static route must be configured on Router 1, and what is the next hop?

**Answer:** `ip route 10.10.20.0/24 10.10.40.2` — the next hop is 10.10.40.2 (Router 2's interface on the shared link).

**Explanation:** Router 1 has no knowledge of 10.10.20.0/24 without a static route because it's not directly connected. The next hop is the IP address of the next router that should receive the packet — in this case Router 2's interface (10.10.40.2) on the link connecting it to Router 1. Router 2 will then deliver the packet to its local 10.10.20.0/24 subnet.
