# Switching Practice Scenarios

## Scenario 1: Native VLAN Mismatch

**Scenario:** You connect two switches via a trunk link. Shortly after, you notice error messages appearing in the switch logs on both sides. Traffic between VLANs works fine across the trunk, but management traffic is intermittent.

**Question:** What is the most likely cause, and how do you fix it?

**Answer:** The native VLAN is configured differently on each side of the trunk.

**Explanation:** The native VLAN must be identical on both sides of a trunk. Traffic on the native VLAN traverses a trunk without a VLAN tag, so a mismatch causes frames to be delivered to the wrong VLAN. This generates error messages in the switch log. The fix is to configure the same native VLAN on both trunk interfaces.

## Scenario 2: Speed/Duplex Mismatch

**Scenario:** A user reports their workstation connects to the network but experiences terrible performance when transferring large files. Small operations like DNS lookups work fine. You check the switch port and see the link light is on and the connection is active.

**Question:** What should you check first, and what specific mismatch would cause this symptom?

**Answer:** Check speed and duplex settings. A duplex mismatch causes a connection that operates but with very poor performance under load.

**Explanation:** Mismatched speed causes no connection at all (no link light). Mismatched duplex allows the connection to function but with degraded performance, especially under load. The first troubleshooting step is to verify speed and duplex match on both sides, then move to IP configuration.

## Scenario 3: STP Port States

**Scenario:** A network administrator adds a redundant link between two switches. After cabling, one of the new ports shows a "blocking" state in the switch interface status.

**Question:** Why is the port in a blocking state, and is this a problem?

A) The cable is faulty and needs replacement
B) STP detected a potential loop and blocked the port to prevent it
C) The port speed is misconfigured
D) The VLAN assignment is incorrect

**Answer:** B) STP detected a potential loop and blocked the port to prevent it.

**Explanation:** Two cables between two switches creates a loop. There is no mechanism at the MAC address level to count how many times a frame has been seen, so frames would loop endlessly until switches are overwhelmed. STP (IEEE 802.1D) automatically recognizes and prevents loops by placing redundant ports in a blocking state, where they do not forward any traffic.

## Scenario 4: Jumbo Frames Failure

**Scenario:** A storage administrator configures jumbo frames (MTU 9000) on a server and the NAS it connects to for improved transfer speeds. After the change, the server can no longer communicate with the NAS. Other devices on the network can reach both the server and NAS without issues.

**Question:** What is the most likely cause of the communication failure?

**Answer:** Not all devices in the communication path support jumbo frames. The switches between the server and NAS are still configured for standard 1,500-byte MTU and are dropping the jumbo frames.

**Explanation:** Jumbo frames (up to 9,216 bytes MTU) require ALL devices in the communication path to understand them — switches, routers, and endpoints. Any device that doesn't support jumbo frames will drop the frames, causing communication to fail completely. The fix is to configure jumbo frame support on every device in the path.

## Scenario 5: STP Recovery

**Scenario:** A switch-to-switch link fails in your network. Users on several VLANs report a brief outage of about 40 seconds before connectivity is restored automatically. No administrator intervention was needed.

**Question:** What protocol recovered the network, and what happened during those 40 seconds?

**Answer:** STP (802.1D) detected the link failure, cleared existing configuration, relearned the topology, and transitioned previously blocked ports to forwarding.

**Explanation:** When a link failure is detected, STP clears existing configuration and relearns the network topology. Blocked ports may become forwarding and root ports may shift, allowing the network to recover without creating a loop. Original STP convergence takes 30-50 seconds. RSTP (802.1W) can achieve convergence in approximately 6 seconds.

## Scenario 6: Link Aggregation

**Scenario:** Two core switches are connected by a single 1 Gbps link that has become a bottleneck. The network team wants more bandwidth between them but cannot upgrade to 10 Gbps hardware yet. They connect three additional 1 Gbps cables between the switches.

**Question:** What happens if they simply plug in the extra cables without any configuration? What protocol should they configure instead?

**Answer:** Without configuration, the extra cables create loops and STP blocks redundant ports. They should configure LACP (Link Aggregation Control Protocol) so the switch treats all four links as one 4 Gbps connection.

**Explanation:** Link aggregation (LAG/port bonding) connects multiple interfaces together so the switch interprets them as one large connection, not a loop. LACP automatically configures link aggregation — you configure the interface as LACP, plug in cables, and the underlying configuration happens automatically. LACP traffic is visible between switches in packet captures.

## Scenario 7: VLAN Communication Issue

**Scenario:** A company has a single switch with three departments: Sales on VLAN 10, Engineering on VLAN 20, and HR on VLAN 30. A Sales employee cannot communicate with an Engineering employee even though both are connected to the same physical switch. The company wants them to communicate without buying additional hardware.

**Question:** What type of switch feature would solve this, and what is the interface type used for routing between VLANs on such a device?

A) A trunk port configured between the VLANs
B) A layer 3 switch using SVIs (Switched Virtual Interfaces)
C) Moving both users to the same VLAN
D) Configuring the native VLAN to carry both VLANs

**Answer:** B) A layer 3 switch using SVIs (Switched Virtual Interfaces).

**Explanation:** VLANs create separate broadcast domains — only devices in the same VLAN can communicate directly. A layer 3 switch combines layer 2 switching (MAC-based forwarding) with layer 3 routing (IP-based forwarding) in one device. It can route between VLANs within the same switch using inter-VLAN routing interfaces called SVIs (Switched Virtual Interfaces). Layer 3 functionality may need to be enabled and often requires a switch restart.

## Scenario 8: Voice and Data VLAN

**Scenario:** A company is deploying IP phones at every desk. Each desk has only one ethernet cable running from the switch. The phone and the desktop PC both need network access, but the administrator wants voice traffic separated from data traffic to prevent congestion from affecting call quality.

**Question:** How can both the phone and computer use a single switch port, and how is the traffic separated?

**Answer:** The switch uses trunking on the single cable to carry both a voice VLAN (e.g., VLAN 200) and a data VLAN (e.g., VLAN 100). The cable runs from the switch to the phone, and the computer plugs into the phone.

**Explanation:** Voice requires consistent access and is affected by congestion, while data is bursty. The solution puts voice on one VLAN and data on another. A single cable connects switch to phone to computer. The switch recognizes both phone and computer and uses trunking on the same cable to separate voice and data traffic so neither affects the other. This requires a switch that supports recognizing both devices on the same port.
